## AIS3 Tiny Server - Reverse
1. Initial analysis:
sub_2110: This function reads and parses the HTTP request from the client. It includes logic to check a specific header, then calls `sub_1E20` to validate a potential flag.
sub_1E20: This function contains the core flag-checking logic. It compares the input string with a dynamically generated target string.
2. Request processing and flag trigger (`sub_2110`):
`sub_2110` first reads the HTTP request line (for example, `GET / HTTP/1.1`). After parsing this initial line, it enters a loop to read the following HTTP headers.
The loop (`do { ... } while (v16[0] != 0x33584F41 || v16[1] != 0x616C462D || v17 != 0x67);`) is looking for a very specific header. It keeps looping until it finds a line that starts with the following byte sequence:
`v16[0] == 0x33584F41`: In little-endian, this is `41 4F 58 33`, corresponding to ASCII string `"AOX3"`.
`v16[1] == 0x616C462D`: In little-endian, this is `2D 46 6C 61`, corresponding to ASCII string `"-Fla"`.
`v17 == 0x67`: This is ASCII character `'g'`.
So the server is looking for a header line that starts with `AOX3-Flag`. Once found, the code extracts that header's value part. It skips the `AOX3-Flag` prefix and any following colon or spaces. The resulting string (`p_s`) is then passed to `sub_1E20` for verification.
3. Flag decryption logic (`sub_1E20`)
`sub_1E20` is where the flag is actually hidden and checked. It takes the provided string (from the `AOX3-Flag` header) as input (`a1`). It dynamically generates a 45-byte target flag string and compares the input against it.
4. Extracting the flag

## SlowECDSA
* The key vulnerability in `chal.c` is that ECDSA nonce `k` is generated with an LCG. If an attacker knows two consecutive `k` values, they can recover the private key. Then let AI help write the script!
1. Call `get_example` twice in a row to obtain two signatures for the same message `"example_msg"`:
The first signature `(r1, s1)` uses nonce `k1`
The second signature `(r2, s2)` uses nonce `k2 = (a * k1 + c) mod n`
2. Given:
s1 = k1^(-1) * (h + r1 * d) mod n
s2 = k2^(-1) * (h + r2 * d) mod n
k2 = (a * k1 + c) mod n
where `h` is the hash of message `"example_msg"`, and `d` is the private key.
3. From the equations above, we can solve for `k1 = (h * (r1 - r2) - s2 * c * r1) * inv(s2 * a * r1 - r2 * s1, n) mod n`
4. Once `k1` is obtained, the private key can be computed: `d = (s1 * k1 - h) * inv(r1, n) mod n`
5. Use the recovered private key `d` to sign message `"give_me_flag"`:
Choose a new random nonce `k_flag`
Compute `r_flag = (k_flag * G).x mod n`
Compute `s_flag = k_flag^(-1) * (h_flag + r_flag * d) mod n`

## Stream
* The key insight is that Python's `random` module uses the Mersenne Twister (MT19937) PRNG, which is deterministic. If we can obtain 624 consecutive 32-bit outputs, we can fully predict future outputs.
* Since `getrandbits(256)` is actually formed by concatenating 8 consecutive 32-bit random values (`256/32 = 8`), 80 loop iterations give us `80 * 8 = 640` 32-bit values, enough to recover the internal state of MT19937.

solve.py:
```
from hashlib import sha512
import math
from randcrack import RandCrack

def solve():
    # 1. Parse output.txt
    with open("output.txt", "r") as f:
        output_lines_hex = [line.strip() for line in f.readlines()]
    
    output_values_int = [int(h, 16) for h in output_lines_hex]

    # 2. Precompute all possible SHA-512 hash values
    H_lookup = [int.from_bytes(sha512(bytes([i])).digest(), 'big') for i in range(256)]

    # 3. and 4. Recover r_i values and their 32-bit MT components
    mt_outputs_32bit = []
    
    print("Recovering r_i values...")
    for i in range(80): # First 80 lines
        output_val = output_values_int[i]
        found_match_for_line = False
        for h_candidate_val in H_lookup:
            potential_square = output_val ^ h_candidate_val
            if potential_square < 0: continue

            # Use math.isqrt to compute integer square root
            r_candidate = math.isqrt(potential_square)
            if r_candidate * r_candidate == potential_square:
                if 0 <= r_candidate < (1 << 256): # check whether r_candidate is a 256-bit number
                    # r_i
                    for k_idx in range(8): # 256 bits = 8 * 32 bits
                        u_k = (r_candidate >> (32 * k_idx)) & 0xFFFFFFFF
                        mt_outputs_32bit.append(u_k)
                    found_match_for_line = True
                    break # found a match, stop searching
        
        if not found_match_for_line:
            print(f"Error: Could not find match for output line {i}: {output_lines_hex[i]}")
            return "Failed to recover r_i for all lines."
    
    if len(mt_outputs_32bit) < 640: # Should be 80 * 8 = 640
        print(f"Error: Not enough MT outputs recovered ({len(mt_outputs_32bit)}), expected 640.")
        return "Failed to recover sufficient MT outputs."
    print(f"Recovered {len(mt_outputs_32bit)} 32-bit MT outputs.")

    # 5. Crack Mersenne Twister
    print("Cracking Mersenne Twister state...")
    cracker = RandCrack()
    for j in range(624): # submit the first 624 32-bit outputs
        cracker.submit(mt_outputs_32bit[j])
    print("MT state seeded.")

    # 6. Predict r_flag
    # The 80 loops used u_0 through u_639
    # We have already fed u_0 through u_623 into the cracker
    # Need to predict u_640 through u_647 to obtain r_flag
    # First, advance the cracker state past known values u_624...u_639
    # These are 640 - 624 = 16 values
    print("Advancing cracker state...")
    for _ in range(16): # This loop consumes predictions for u_624 through u_639
        cracker.predict_getrandbits(32)

    # Now predict the 8 components of r_flag (u_640 to u_647)
    print("Predicting r_flag components...")
    r_flag_components_pred = []
    for _ in range(8):
        pred_u_k = cracker.predict_getrandbits(32)
        r_flag_components_pred.append(pred_u_k)

    r_flag_predicted_int = 0
    for k_idx in range(8): # Assemble r_flag from its 8 components
        r_flag_predicted_int |= (r_flag_components_pred[k_idx] << (32 * k_idx))
    print(f"Predicted r_flag: {hex(r_flag_predicted_int)}")

    # 7. Compute flag
    o_flag_val = output_values_int[-1] # the final output line contains the flag

    int_flag = o_flag_val ^ (r_flag_predicted_int**2)

    if int_flag == 0:
```

1. We need to recover LCG parameters `a` and `b` from the hints. We know:
h0 = (a * seed + b) % M
h1 = (a * h0 + b) % M
h2 = (a * h1 + b) % M
`a` can be solved using `h1 - h0 = a * (h0 - seed) % M`
`h2 - h1 = a * (h1 - h0) % M`
From the second equation, we get `a = ((h2 - h1) * inverse(h1 - h0, M)) % M`
Then use `a` to compute `b`: `b = (h1 - a * h0) % M`
2. `q` is obtained by applying `genPrime()` to `p`. `genPrime()` does:
Compute `x = rng(input_value)`
If `x` is not prime, repeat `x = rng(x)` until `x` is prime
This means `q` is obtained by applying the LCG to `p` multiple times: `q = rng^j(p) = (A_j * p + B_j) % M`
3. Since `n = p * q` and `q = (A_j * p + B_j) % M`, we derive: `n/p ≡ A_j * p + B_j (mod M)`
Multiply both sides by `p` (assuming `p` is not a multiple of `M`): `n ≡ A_j * p² + B_j * p (mod M)`
This becomes a quadratic congruence: `A_j * p² + B_j * p - n ≡ 0 (mod M)`
4. Solve the quadratic congruence to find `p`
For each possible `j`, compute `A_j` and `B_j`
Solve quadratic congruence `A_j * x² + B_j * x - n ≡ 0 (mod M)`
5. Once the correct `p` and `q` are found:
Compute `phi = (p - 1) * (q - 1)`
Compute `d = inverse(e, phi)`
Decrypt `m = c^d mod n`
Convert `m` to bytes to obtain the flag
